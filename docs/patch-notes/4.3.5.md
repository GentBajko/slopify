# Slopify 4.3.5

Released 12 November 2026.

The picture is now timed to the narration, a run no longer takes the whole computer, and a video's shorts stay in Ready to upload until every one of them is up.

## Each image holds for its share of the narration

- **A shot's length is now worked out from the narration it covers** — the time left after the figure cards, divided by the number of images — rather than from a fixed number of seconds. The images a video was made with span the whole video, in order, each one once.
- **A sparse set still keeps cutting.** Where dividing the narration that way would leave one image on screen for more than two minutes, the shot falls back to the length set for the project, so the picture keeps moving rather than settling on a still.
- **Measured on a real episode:** 240 images now plan 244 shots across the whole timeline.

## This computer renders one video at a time

- **Settings → Production defaults → Videos rendered at once,** one to four, one by default. A render decodes a whole picture track and encodes hours of it, so a second one does not take half the time each: they share the processor, the disk and the memory, and enough of them together leave the app with too little of each to answer the page.
- **A render that has to wait is not refused,** it takes its turn and finishes later. Shorts queue beside long videos, since a short is a render like any other.
- **The audio export does not queue.** It is neither long enough nor heavy enough to be worth holding a place for, so turning narration into a WAV never waits behind a video.
- **The number is read as each render asks for its place,** so raising it lets a waiting render start without a restart, and lowering it takes hold as the renders running now finish.

## A video's shorts stay in Ready to upload until they are up

- **The project's uploaded mark now stands for every upload it has,** the long video and each short, not for the long video alone. It was one fact before — the long video on YouTube meant the project was uploaded — and that quietly took the shorts still waiting out of Ready to upload with it.
- **Why it bit:** Studio re-reads the long video after each upload. Uploading short 1 made Slopify record the long video again, which re-applied the mark, which hid shorts 2 and 3. The extension then said "Nothing waits to be uploaded" while two shorts had never gone up, and taking the mark off by hand lasted only until the next upload re-applied it.
- **Nothing changed about what the extension already knew:** every item in its list carried its own uploaded flag all along. Only the project-level mark was wrong, so Projects, Home, the calendar and the extension now agree without any of them being taught about shorts.
- **Forgetting an upload that was on YouTube takes the mark off again,** a short's as well as the long video's, since the mark stands for all of them. An upload only filled in Studio never set the mark, so forgetting it still leaves a mark made by hand.

## New images appear as they are made

- **The open page now hears about each image as it lands,** so the pictures fill in while a run works instead of only when you reload. The progress beside them already moved live; the pictures themselves did not.
- **A long run does not flood the page.** A run of 240 images collapses into a few refreshes rather than one for every image.
