# Subtitle timing model

- **English captions are now timed with the full-precision speech model by default.** The 95 MB int8 model misheard lines on real narrations and stopped runs with a false "Subtitles stopped matching the audio", which records narration again at a cost. Measured on a 2 h 28 min narration on the same computer, back to back: fp32 (378 MB) aligned in 2 min 40 s with a 1.1 GB peak and heard both problem lines right; fp16 (189 MB) took 3 min 16 s, 1.2 GB, also right; int8 (95 MB) took 5 min 35 s, 0.7 GB, and misheard both. Bigger is more accurate and, on that computer, faster too.
- A new **Subtitle timing model** choice in Settings → Production defaults: Most accurate (378 MB, recommended), Balanced (189 MB) or Smallest (95 MB, less accurate). It belongs to this computer, not a project. The chosen model downloads once, on first use (and at start unless `SLOPIFY_NO_MODEL_PREFETCH` is set); models already downloaded stay, so switching back costs nothing. An alignment that is running keeps the model it started with; the next one uses the new choice.
- Changing the model never marks subtitles outdated: all three are the same pinned `Xenova/wav2vec2-base-960h` revision timing the same words, and the timing fingerprint (`wav2vec2-en-a19f851-v2-omissions`) does not include the precision.
- The Docker image now carries the fp32 model as its seed instead of int8 (verified against its size and SHA-256 at build time), so a new container needs no download with the default setting.
