# Antigravity CLI replaces the Gemini CLI

- **The Gemini CLI text provider is now the Antigravity CLI (`agy`).** Google retired the Gemini CLI for personal accounts on 2026-06-18 and moved them to Antigravity. Settings → Providers shows **Antigravity CLI** where Gemini CLI was; projects that chose it keep their choice. Install it with `curl -fsSL https://antigravity.google/cli/install.sh | bash`, then run `agy` once in a terminal to sign in with your Google account.
- Slopify runs `agy` headless (`--input-format stream-json --output-format stream-json`) in an empty private folder, without `--dangerously-skip-permissions`, so it can't run commands or touch your files. Research notes are written into the prompt instead of being read through a tool.
- The model list comes from `agy models` (for example `gemini-3.8-flash-high`). A model saved for the old Gemini CLI, such as `gemini-2.5-pro`, isn't on that list: pick a new one in Edit project → Providers.
- **What it can't do that the Gemini CLI did:** it can't search the web, so a research step with web search stops and asks you to choose another text provider or turn Research off. It also can't look at pictures, the same as the Gemini CLI. Slopify can't tell from files whether a Google sign-in is valid because `agy` keeps it in the system keyring, so the health check shows "could not tell" unless you use API-key mode (`"modelProvider": "gemini"` in `~/.gemini/antigravity-cli/settings.json` plus `GEMINI_API_KEY`).
- Error messages name the fix. A signed-out `agy` says to run `agy` and sign in. An unknown model says to run `agy models` and pick one. A used-up Antigravity quota waits and tries again by itself. A saved program path that still points at `gemini` says to clear it or point it at `agy` in Settings → Providers.
- In Docker, the host helper now looks for `agy` on the host's PATH, where it used to look for `gemini`.
