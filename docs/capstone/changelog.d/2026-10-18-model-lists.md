# Model lists that are always true

- **Model pickers show the models that work for you.** Each picker now badges every model: ✓ works (checked or used, and when), ? listed for you, ? not checked, ✕ not on your plan with the provider's own words, ⚠ retiring with its date and replacement. By default a picker lists the working models plus the one already chosen, which stays visible and selected whatever its badge; before anything works it lists what your key lists, then everything, so it is never empty. **Show all** brings back the rest. A model marked not on your plan still runs exactly as before if it is chosen: badges never change what a run does.
- **Settings → Models → Models that work for you.** One row per provider you set up: what works, what is listed, what is not on your plan, when it was last checked and what checks have cost. **Check models** sends each model the smallest request (a one-word reply, a spoken "Hi", one small square image) and shows the price at list rates first whenever it costs anything; nothing is sent until you confirm. CLI checks use the plan's allowance. Image-to-video models are listed, never checked.
- **Automatic checks.** When you save a key, when a CLI becomes usable, and weekly, Slopify reads the key's own model list and checks the models you use, those that already worked and newly listed ones - only when a check is free, uses a CLI plan, or costs well under a tenth of a cent. Images are never checked by themselves. Turn it off in Settings → Models → Automatic checks; `SLOPIFY_NO_MODEL_REFRESH=1` turns it off with the daily catalogue check.
- **Learn from real runs.** A model a run used is marked working, and one the provider refuses as not on your plan or not found is marked at once, with its sentence.
- **New for you.** Models that start working for you after the first check are listed under Settings → Models → New for you, and Home shows "2 new models work for you" until you dismiss them.
- **Retirement dates.** A separate `models-lifecycle.yaml`, downloaded with the daily catalogue check, says when a model retires and what replaces it; the retired-models switch prefers that replacement. `models.yaml` keeps its exact shape, so older versions keep reading it.
- **Agents.** `list_models` now returns each model's standing; `get_model_checks`, `estimate_model_checks`, `check_models` (asks first, worded from the estimate) and `dismiss_model_notices` mirror Settings → Models. Automatic checks stay the person's setting.
- **Catalogue upkeep.** A daily GitHub Action proposes `models.yaml` changes from OpenRouter's public metadata (prices, context, output limits, thinking, new and retired models) as one pull request, "Models: 3 new, 1 retired, 2 price changes".
