## Side-effect boundaries

- **Composition root.** `boot` and `wireRunner` inject clock, IDs, paths, SQLite, registry, FFmpeg, hub and telemetry into slices; the runner receives stage implementations it may not import (`packages/app/src/main.ts:815`, `packages/app/src/main.ts:836`). Recipes are computed as pure values before persistence or provider work (`packages/app/src/slices/rebuild/recipe-build.ts:28`).
- **SQLite.** `transact` issues a fixed-name `SAVEPOINT`, nests inside an outer transaction, and throws on an async callback (`packages/app/src/kernel/db/tx.ts:9`). Filesystem writes, FFmpeg, provider calls and SSE emission are outside SQLite atomicity.
- **Disk.** Assets are written and sealed before registration and discarded in `finally` when unregistered (`packages/app/src/slices/storage/assets.ts:68`, `packages/app/src/slices/storage/assets.ts:88`). Backups write atomically into the backup folder (`packages/app/src/slices/backups/files.ts:41`). Backup import stages into `<data>/imports/<id>` and renames into place inside the commit, reversing renames on failure (`packages/app/src/slices/storage/backup-import.ts:170`, `packages/app/src/slices/storage/backup-import.ts:692`, `packages/app/src/slices/storage/backup-import.ts:984`).
- **Providers.** Network and CLI calls happen only inside `attempt` under the queue and deadline; slices get `StageProviders` (`packages/app/src/kernel/runner/attempt.ts:73`, `packages/app/src/kernel/runner/providers.ts:116`). CLI adapters spawn with argv arrays, stdin input and a private process group (`packages/app/src/adapters/llm/run-cli.ts:55`). In Docker, CLI work crosses to the host helper over a Unix socket (`packages/app/src/adapters/host-cli/transport.ts:39`).
- **Subprocesses.** FFmpeg for video (several at once through `inPool`), shorts, loudness, peaks, style previews and duration probing (`packages/app/src/slices/video/ffmpeg.ts:581`, `packages/app/src/slices/video/pool.ts:33`, `packages/app/src/main.ts:478`, `packages/app/src/main.ts:607`, `packages/app/src/main.ts:622`). jsPDF renders documents in-process (`packages/app/src/slices/document/render.ts:1`).
- **Outbound HTTP outside providers.** Notification URL POST (`packages/app/src/slices/notifications/send.ts:13`), telemetry collector (`packages/app/src/slices/telemetry/collector-client.ts:40`), catalogue sync (`packages/app/src/catalog/store.ts:195`), update registry (`packages/app/src/main.ts:432`). - **Events.** `hub.emit` is fire-and-forget; write failures are caught per subscriber (`packages/app/src/edge/events/hub.ts:101`). Observers (notifier, episode watcher) run after page delivery and do their IO asynchronously (`packages/app/src/edge/events/hub.ts:202`, `packages/app/src/slices/episodes/summarize.ts:210`).
- **Mutation gating.** Every write request, timer mutation and backup holds an updater lease so installs never overlap writes (`packages/app/src/edge/http/app.ts:258`, `packages/app/src/main.ts:658`, `packages/app/src/slices/backups/service.ts:256`).

## Failure paths

- **Stage failure.** `execute` catches: aborted → `pending` (pause) or `canceled`; waitable fault with a persisted wait → `pending` with `retryAt`; otherwise logs and concludes `failed` with the fault kind (`packages/app/src/kernel/runner/index.ts:215`). `runRevisionInvocation` marks the piece `pending` (aborted) or `failed` and rethrows with a piece label (`packages/app/src/slices/rebuild/runtime-run.ts:51`). If writing the final row fails, the row stays `running`, the event still goes out and the next boot marks it interrupted (`packages/app/src/kernel/runner/index.ts:147`, `packages/app/src/main.ts:1017`). A throwing `stagesOf` during the post-run tick still re-tallies in `finally`; an escaped `execute` rejection is logged (`packages/app/src/kernel/runner/index.ts:258`, `packages/app/src/kernel/runner/index.ts:264`).
- **Provider attempt.** Aborted calls end the attempt row `canceled` and rethrow; other failures are classified, logged and retried within tier 1; terminal kinds, plan limits, exhausted attempts or long Retry-After throw to the stage (`packages/app/src/kernel/runner/attempt.ts:117`, `packages/app/src/kernel/runner/attempt.ts:141`).
- **Publication partial failure.** A failed publication transaction rolls back rows; `finally` deletes unregistered prepared files; a deletion failure leaves orphans for boot reconciliation (`packages/app/src/slices/rebuild/runtime-publication.ts:135`, `packages/app/src/slices/storage/reconcile.ts:14`).
- **Save revision.** Validation refusals return typed results; a head that moved during the transaction throws and rolls back; `finally` discards unregistered assets (`packages/app/src/slices/revisions/mutations.ts:205`, `packages/app/src/slices/revisions/mutations.ts:228`). Receipts make a resent request replay rather than mutate again (`packages/app/src/slices/revisions/mutations.ts:80`).
- **Rebuild.** Readiness exceptions become a logged `readiness` refusal before the lock; stale head/plan/cost returns `conflict`/`stale-preview` (`packages/app/src/slices/rebuild/service.ts:137`, `packages/app/src/slices/rebuild/service.ts:177`).
- **Play Start.** Expected refusals release the `starting` claim; `StartedRunMismatch` rolls back and releases; other exceptions after the claim propagate and leave durable `starting` state that a retry with the same review ID resumes. Post-commit actions catch and log independently (`packages/app/src/slices/play-drafts/start.ts:71`, `packages/app/src/slices/play-drafts/start.ts:100`, `packages/app/src/slices/play-drafts/start.ts:180`).
- **HTTP.** Uncaught route errors reach `problemFromError`: logged with a correlation ID, generic 500 to the client (`packages/app/src/edge/http/problem.ts:44`). Writes during shutdown get 503; writes during an update install get 409 (`packages/app/src/edge/http/app.ts:244`, `packages/app/src/edge/http/app.ts:260`).
- **SSE.** A rejected `writeSSE` (data or heartbeat) drops the subscriber and logs; request abort removes it. The hub keeps no replay log beyond the tally and preview snapshots (`packages/app/src/edge/events/hub.ts:104`, `packages/app/src/edge/events/hub.ts:136`). In the browser, a reconnect `open` triggers refetch (project) or full invalidation (global) (`packages/web/src/events.ts:161`, `packages/web/src/components/shell.tsx:350`). The mux drops frames whose JSON does not parse; `events.ts` `parse` has no local catch, and a frame whose `type` differs from its event name is ignored (`packages/web/src/event-mux.ts:70`, `packages/web/src/events.ts:173`, `packages/web/src/events.ts:185`). A dead mux connection affects every view on the page at once, since all share it (`packages/web/src/event-mux.ts:54`).
- **Schedules.** Overlapping ticks return immediately; claims are version-checked; `execute` records `ScheduleDispatchError` reasons or `The scheduled run failed.`; a tick rethrows the first rejected run after all settle and the lifecycle logs `schedule.tick`; boot and each tick turn abandoned `running` runs into failures (`packages/app/src/slices/schedules/scheduler.ts:75`, `packages/app/src/slices/schedules/scheduler.ts:87-89`, `packages/app/src/slices/schedules/scheduler.ts:227-233`, `packages/app/src/main.ts:195`, `packages/app/src/slices/schedules/repo.ts:421`). A continued prepared project records the run `succeeded` without a draft; a prepared project canceled since is skipped and the day starts a new one (`packages/app/src/slices/schedules/scheduler.ts:186-191`, `packages/app/src/slices/schedules/prepare.ts:148-153`). `prepareTopic` refusals (`not-found`, `missing-template`, `already-prepared`, review reasons with field messages, `spend-limit`) are returned values (`packages/app/src/slices/schedules/prepare.ts:65-103`). Topic generation failures are logged; the lease expires after the generation timeout plus 5 min (`packages/app/src/slices/schedules/scheduler.ts:50-57`, `packages/app/src/slices/schedules/topics.ts:31`).
- **Backups.** Busy projects record a waiting status; plan failures record a failed status; write failures record an explained failure; prune failure keeps the success with a warning detail; shutdown aborts the write and removes the partial file (`packages/app/src/slices/backups/service.ts:263`, `packages/app/src/slices/backups/service.ts:271`, `packages/app/src/slices/backups/service.ts:127`, `packages/app/src/slices/backups/service.ts:114`, `packages/app/src/slices/backups/service.ts:282`, `packages/app/src/main.ts:765`). Import validation failures become `BackupImportRefused`; `finally` closes the scratch DB, deletes the work folder and clears the in-progress flag; a failed commit rolls back rows and reverses renames best-effort, leaving reconciliation to remove uncommitted project folders (`packages/app/src/slices/storage/backup-import.ts:241`, `packages/app/src/slices/storage/backup-import.ts:984`). Legacy ZIP import failures return 400 (`packages/app/src/edge/http/storage.ts:169`).
- **Notifications.** Send failures and timeouts are logged, never retried; observer exceptions are caught and logged (`packages/app/src/slices/notifications/notifier.ts:85`, `packages/app/src/slices/notifications/notifier.ts:117`).
- **Timers.** Queue, retry and trash timers catch, log and release the lease in `finally`; backup tick rejections are logged (`packages/app/src/main.ts:662`, `packages/app/src/main.ts:678`, `packages/app/src/main.ts:704`, `packages/app/src/main.ts:722`).
- **Studio extension.** `/ext` calls without the paired token and origin answer 401; Prepare-page writes from another origin answer 403 (`packages/app/src/edge/http/studio.ts:202-208`, `packages/app/src/edge/http/studio.ts:179-188`). The worker turns every failure into `{ ok: false, message }` for the page (`packages/extension/src/background.ts:402-403`); a failed `/ext/tasks` or `/ext/known-videos` read becomes an empty list (and `checks:false`) and an oEmbed failure counts as not public, so the alarm simply retries (`packages/extension/src/background.ts:162-166`, `packages/extension/src/background.ts:141-143`, `packages/extension/src/background.ts:224`). A Studio-side failure is reported through `/ext/task-result` as `failed` with its message (`packages/app/src/edge/http/studio.ts:759-765`). During Upload all, a short whose file is still uploading after 3 h stops the chain with an error toast and the next short is not opened (`packages/extension/src/content.ts:258-264`). A project with no free plan time, or a plan with no lines, gets no release and its items no `scheduleAt` (`packages/app/src/slices/studio/releases.ts:149-150`, `packages/app/src/slices/studio/plan.ts:24-26`). An upload cancelled in Studio stays `filled` and is offered again (`packages/app/src/kernel/db/migrations/0046-youtube-upload-state.sql:1-4`).
- **Video render.** The first failing pooled FFmpeg run aborts the others and is the error thrown (`packages/app/src/slices/video/pool.ts:29-33`); a clip is kept in the cache whole or not at all (`packages/app/src/slices/video/clip-cache.ts:66`).
- **Telemetry.** Retriable failures leave events queued; shutdown stops the flusher without waiting, so an in-flight batch may be resent and deduplicated by event ID; the collector's insert and aggregate bumps are separate statements (`packages/app/src/slices/telemetry/flush.ts:55`, `packages/app/src/main.ts:793`, `packages/collector/src/index.ts:79`).
- **Boot.** Any initialization error closes SQLite, releases the lock and rethrows (`packages/app/src/main.ts:808`). Storage reconciliation failure after an update activation is logged and retried on the next restart (`packages/app/src/main.ts:415`).
