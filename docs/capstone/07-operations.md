## Configuration

CLI flags override their environment counterparts, then defaults. `--no-open` unconditionally disables opening; otherwise empty, `0` and `false` are false and other nonempty values are true. Ports must be integers from 1 to 65535 and data paths resolve against the current working directory (`packages/app/src/kernel/config/index.ts:23`).

The preceding native port/data rules do not select Docker storage. With `--docker`, `--host` and `--data-dir` are rejected; `--projects-dir` is rejected without `--docker`. Docker `--port` overrides `SLOPIFY_DOCKER_HOST_PORT`, and `--projects-dir` overrides `SLOPIFY_DOCKER_PROJECTS_DIR`. The installer accepts host ports 0–65535; 0 requests an ephemeral localhost port. Relative project overrides resolve against the invoking working directory, and a leading `~/` resolves against the invoking user's home (`packages/app/src/edge/cli.ts:29`, `packages/app/src/edge/cli.ts:79`, `packages/app/src/edge/docker-projects/state.ts:146`).

Project selection is explicit override → verified receipt → existing writable `/data/projects` bind → name-derived default. Saved authority is validated before selection: an override does not bypass a missing/replaced remembered folder, conflicting volume or inconsistent container. A verified failed publication can be reused only while its directory identity, copied digest and original source baseline still agree (`packages/app/src/edge/docker-projects/state.ts:216`, `packages/app/src/edge/docker-projects/install.ts:81`).

Defaults below redact values by variable name, case-insensitively, for `*_SECRET`, `*_TOKEN`, `*_PASSWORD` and `*_KEY`, including internal values and placeholders.

The inventory distinguishes application inputs from values deliberately set for children. Provider keys are SQLite values, not environment configuration consumed by Slopify's provider adapters (`packages/app/src/slices/settings/repo.ts:18`, `packages/app/src/kernel/db/migrations/0001-init.sql:11`).

### Docker project-folder migration and recovery

Managed storage requires a native Linux daemon reached through a local Unix socket. Docker Desktop, remote/TCP endpoints, rootful userns-remap, non-Linux daemons and custom/remote volume configurations are refused. Supported rootless mapping still has to pass a real bind-write probe proving the invoking host UID/GID, private permissions and host write access; the launcher does not disable user namespaces (`packages/app/src/edge/docker-projects/engine.ts:199`, `packages/app/src/edge/docker-projects/engine.ts:268`, `packages/app/src/edge/docker-projects/engine.ts:286`).

Before replacement, the installer validates saved daemon/volume/directory identities, container claims, source access, destination safety, image version and mapping. All containers, including stopped/read-only claimants, participate in named-volume ownership checks; running writable mounts are checked separately for volume or overlapping project paths. Recovery-shaped names alone grant no ownership (`packages/app/src/edge/docker-projects/install.ts:36`, `packages/app/src/edge/docker-projects/claims.ts:6`, `packages/app/src/edge/docker-projects/engine.ts:149`, `packages/app/src/edge/docker-projects/engine.ts:161`).

Replacement disables the previous container's restart policy and stops it, verifies the source, clones and verifies the private volume, then copies projects into a sibling `.slopify-projects-<UUID>` directory. Streamed verification includes every relative name, empty directory, file size and file byte; project symlinks, multiply linked files and special entries are refused. Source digests are checked before and after copying. Verified staging is published by rename only if destination identity/emptiness still agrees. Private-volume ownership conversion excludes its original projects subtree (`packages/app/src/edge/docker-projects/install.ts:184`, `packages/app/src/edge/docker-projects/tree.ts:94`, `packages/app/src/edge/docker-projects/volume.ts:18`, `packages/app/src/edge/docker-projects/volume.ts:52`).

The candidate starts with restart disabled and provisional activation. The launcher allows 120 seconds for both `/api/health` and authenticated `/api/update/ready` to report the exact expected version; individual probes are bounded to two seconds. Receipt commit precedes restart-always and the committed activation marker. During provisional startup, storage reconciliation is deferred, mutation routes are held except activation, and queue/schedule mutation admission remains gated (`packages/app/src/edge/docker-projects/engine.ts:429`, `packages/app/src/edge/docker-projects/install.ts:237`, `packages/app/src/main.ts:190`, `packages/app/src/main.ts:374`, `packages/app/src/main.ts:411`, `packages/app/src/edge/http/app.ts:139`).

Before receipt commit, verified rollback restores private bytes and ownership while excluding projects, retains the failed candidate, and restores the original container's name/restart policy/running state. The durable `restored` phase prevents a repeated rollback from restoring private bytes again after the original has restarted. After receipt commit, rerun finishes activation only after the committed journal, container identity and mounts match the receipt. A missing committed container can be recreated from the remembered storage; missing/replaced storage is refused (`packages/app/src/edge/docker-projects/recover.ts:19`, `packages/app/src/edge/docker-projects/committed.ts:11`, `packages/app/src/edge/docker-projects/volume.ts:30`, `packages/app/src/edge/docker-projects/install.test.ts:184`, `packages/app/src/edge/docker-projects/install.test.ts:379`).

Original project sources, partial staging, published copies, recovery volumes, stopped previous/failed containers and transaction records are retained. The exception is a stopped copy reader whose transaction label, image and complete allowed mount shape match its journal; that reader is removed before checking claims. Conflicting readers/containers, changed directories or daemon/volume identities, inconsistent records, unsafe destinations and stale copied baselines are refused. Failed unreceipted bind adoption retains the original bind/container as authority and never falls back to hidden volume projects. A stale published copy requires retained recovery material and a new empty `--projects-dir` for a fresh verified copy (`packages/app/src/edge/docker-projects/claims.ts:30`, `packages/app/src/edge/docker-projects/install.ts:61`, `packages/app/src/edge/docker-projects/install.ts:191`, `packages/app/src/edge/docker-projects/install.ts:270`, `README.md:115`).

Managed project trees belong to storage reconciliation, so unrelated documents are not part of their supported contents. Installation backups require both private volume and host projects; the portable settings archive is not a project/history backup. Temporary migration capacity includes a volume clone and project copy (`README.md:62`, `README.md:106`, `packages/app/README.md:119`).

Current and retained-output folder actions validate the recorded output and return its parent under the host project path with `location: "docker-host"` and `Cache-Control: no-store`. When the host CLI helper is installed, the container asks it to open that folder (`POST /v1/open-folder`); the helper opens only real, user-owned folders inside a launcher receipt's projects directory whose dev/ino still match, and launches `xdg-open` detached, so the reply is `opened: true`. Without a helper, or with an older one, the reply is `opened: false` with the path (`packages/app/src/host-cli/open-folder.ts`). API-only managed installations support the path reply without a host helper; unmanaged Docker returns actionable 503 while downloads remain available. Native opening remains unchanged. The UI identifies the path as belonging to the machine running Slopify and exposes a read-only field that selects on focus (`packages/app/src/edge/http/open-folder.ts:34`, `packages/app/src/edge/http/revision-files.ts:53`, `packages/app/src/edge/http/folder-location.ts:18`, `packages/web/src/project/open-folder.tsx:67`).

## Play drafts and tutorial recovery

Migration 0006 adds `play_drafts`, `play_draft_attachments` and `play_start_receipts` to the existing app SQLite database. Draft content, section, variants and expected-word input live in the app data directory; browser localStorage remembers only the active draft identifier. An empty visit creates no record, the first edit starts creation, and subsequent edits debounce saves for 500 ms. Only acknowledged generations are reported saved; failed or conflicting writes retain local input and offer Retry, Reload saved draft or Save as a new draft (`packages/app/src/kernel/db/migrations/0006-play-drafts.sql:1`, `packages/web/src/play/draft-restore.ts:6`, `packages/web/src/play/use-draft-session.ts:77`, `packages/web/src/play/use-draft-session.ts:156`, `packages/web/src/play/draft-list.tsx:116`).

Completed attachment bytes are retained by server ownership rather than browser storage. Fork creates independent attachment IDs sharing ready staged files; discard removes the draft and releases only unshared files. Start copies supplied inputs into every project before releasing draft ownership. Metadata deletion and byte cleanup both respect other draft references, including when a revision Save consumes the same staged input; cleanup defers during an outer transaction or active copy. Missing/interrupted uploads require reattachment instead of being admitted as complete (`packages/app/src/slices/play-drafts/service.ts:212`, `packages/app/src/slices/play-drafts/service.ts:266`, `packages/app/src/slices/play-drafts/start.ts:95`, `packages/app/src/slices/storage/repo.ts:93`, `packages/app/src/slices/storage/staging-refs.ts:14`, `packages/app/src/slices/revisions/mutations.ts:188`, `packages/app/src/slices/storage/reconcile.ts:69`).

Current Play uses draft Review and Start endpoints for both single runs and batches. Review binds saved inputs, current templates/catalogue and owned files without creating projects. Explicit Start claims the review identity, checks readiness, then atomically creates project/queue/revision work records, its receipt and the draft ownership transition. A lost response or restart reuses that receipt before resolving consumed staging; conflicting identity cannot create another run. Uncaught readiness/infrastructure failures can leave a durable pending claim, and the browser restores it as uncertain until the same Start is resolved. Post-commit telemetry, cleanup or runner-notification failures are logged without invalidating receipt success (`packages/app/src/edge/http/drafts.ts:113`, `packages/app/src/slices/play-drafts/review.ts:49`, `packages/app/src/slices/play-drafts/start.ts:31`, `packages/app/src/slices/play-drafts/start.ts:91`, `packages/app/src/slices/play-drafts/start.ts:95`, `packages/app/src/slices/play-drafts/start.ts:133`, `packages/app/src/slices/play-drafts/start-repo.ts:66`, `packages/web/src/play/review-state.ts:128`, `packages/web/src/play/review-state.ts:212`).

The Drafts list excludes started records; confirmed creation clears the active browser identifier and navigates to the first created project, while durable receipts remain available even after explicit draft deletion. Malformed or unsupported draft content is preserved as unreadable metadata for recovery/discard (`packages/app/src/slices/play-drafts/repo.ts:43`, `packages/web/src/play/use-draft-session.ts:310`, `packages/web/src/routes/play.tsx:126`, `packages/app/src/kernel/db/migrations/0006-play-drafts.sql:29`, `packages/app/src/slices/play-drafts/service.ts:104`, `packages/app/src/slices/play-drafts/service.ts:146`).

Tutorial progress uses the server settings key `tutorial.session`, with schema/version and exact mutation replay checks. Browser transitions are serialized, restored step IDs map to current tutorial positions, and stored prompt/project IDs are checked before resume. Unreadable progress is retained until explicit Restart deletes the record; save conflicts report an error without replacing the other writer. Play targets reveal their owning section before spotlight measurement (`packages/app/src/slices/settings/tutorial.ts:34`, `packages/app/src/slices/settings/tutorial.ts:57`, `packages/app/src/slices/settings/tutorial.ts:80`, `packages/web/src/tutorial/use-session.ts:33`, `packages/web/src/tutorial/use-session.ts:84`, `packages/web/src/tutorial/runner.tsx:86`).
