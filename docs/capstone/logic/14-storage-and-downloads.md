# 14 Storage and downloads

Project revisions retain immutable media under each project's folder. The database, settings, models, logs and staging stay in the data directory; project folders, scheduled backups and exports live in a user-visible files root that a native install can move. Deleting a project moves it to the trash for 30 days; only Delete now or the daily purge removes its folder. There is no automatic revision purge.

## Trigger & preconditions

App startup settles the files location and reconciles disk records (`packages/app/src/main.ts:254-282`). Save, provider settlement and local rendering prepare assets for transactional publication. Current outputs and History expose downloads. Settings → Backup & storage exposes Disk space, Keep outputs only, Clean orphan files, Export everything / Import, Your files (move and Open folder); Settings → Backups the schedule; Settings → Trash restore and Delete now. The project page offers Free space once a project has finished (`packages/web/src/project/free-space.tsx:20`). Trashing, Delete now, export, scheduled backup and moving files each refuse while the project(s) involved are busy (sections below).

## Steps

1. **Data directory.** Default `~/.slopify` or `--data-dir` / `SLOPIFY_DATA_DIR` (`packages/app/src/edge/cli-args.ts:68`). `layout()` places `slopify.db`, `staging/`, `logs/`, `.lock` there; without a files layout, projects are `<dataDir>/projects` and backups `<dataDir>/projects/Backups` (`packages/app/src/kernel/paths.ts:31-44`). Data dir, staging and logs are forced to mode `0700` (`packages/app/src/kernel/paths.ts:62-73`).
2. **Files location.** `settleFilesLocation` decides once per install and stores `files.location` as `{kind:"data-dir"}` or `{kind:"root",root}`. An existing database keeps `data-dir`; a fresh install (when the Documents lookup is enabled) takes `<Documents>/Slopify`, or `Slopify 2` … `Slopify 20`, the first whose `Projects` is empty or missing (`packages/app/src/slices/storage/files-location.ts:81-97`). A root holds `Projects/`, `Backups/` and `Exports/` (`packages/app/src/slices/storage/files-location.ts:44-53`). A container ignores the setting and uses the installer's mounts: `/data/projects`, and `/data/backups` when `SLOPIFY_DOCKER_BACKUPS_DIR` is set, else `projects/Backups` (`packages/app/src/edge/docker-install/activation.ts:27-36`). `repoint` mutates the shared `Paths` object in place so every slice reads the new folders (`packages/app/src/kernel/paths.ts:48-54`).
3. **Assets.** `allocateAsset` creates `assets/<ulid>/<filename>` under the project folder (mode `0700`), rejecting non-basename names; bytes are written, sealed, probed, then registered in the revision manifest transaction. Revisions share registered assets instead of copying unchanged bytes (`packages/app/src/slices/storage/assets.ts:26-45`, `packages/app/src/slices/storage/prepare.ts:24`, `packages/app/src/slices/revisions/mutations.ts:58`). Every path resolves through `contained()`, which throws for anything resolving outside the project root (`packages/app/src/slices/storage/layout.ts:38-47`). The clips of a project's last video render live outside its folder, in the hidden `<projects root>/.render-cache/<projectId>` (`renderCacheFolder`/`renderCacheDir`, `packages/app/src/slices/storage/layout.ts:9-16`; scenario 11): disposable, so it is not in project backups (which walk only `projectDir`, `packages/app/src/slices/storage/backup-export.ts:302`) and a render re-encodes what is missing. Legacy output files use role-fixed names from `outputFileName` (`video.mp4`, `document.pdf`, `description.txt`, `shorts/short-NN`, `images/NNN`, …) (`packages/app/src/slices/storage/layout.ts:53-133`).
4. **Revision records.** A revision output record identifies role/slot, originating work, asset and fingerprint. Selection can change while earlier records stay retained; narration pieces have immutable revision records (`packages/app/src/slices/revisions/manifest-repo.ts`, `packages/app/src/slices/rebuild/runtime-publication.ts`).
5. **Current downloads.** `GET /files/:projectId/:asset` resolves the project, finds the output whose `assetOf()` equals `asset`, stats the file and names it `<title-slug>-<asset><ext>`; the slug is NFKD-folded, `[a-z0-9-]`, at most 60 characters, `project` when empty (`packages/app/src/slices/storage/downloads.ts:56-108`). The YouTube roles (`youtube_description`, `youtube_tags`, `youtube_pinned_comment`, `youtube_titles`) are served as the page shows them: hand edits, fitted chapters and links applied through `effectiveDescription`, while the file on disk stays the generated text (`packages/app/src/slices/storage/downloads.ts:92-149`). Other files honour one `bytes=` range (206 / 416) so players can seek (`packages/app/src/edge/http/byte-range.ts:6-48`); `?waveform=N` answers the audio player's bars instead of the file (`packages/app/src/edge/http/files.ts:52-56`). `GET /files/:projectId/images.zip` stores (level 0) every image and thumbnail output, skipping missing files (`packages/app/src/slices/storage/downloads.ts:152-180`).
6. **Retained downloads.** `GET /files/:projectId/revisions/:revisionId/:recordId` checks project, revision and record ownership (`revision_outputs` then `revision_pieces`) before any path lookup, and names the file from that revision's own title, so later title edits do not rename old downloads; pieces download as `<slug>-<stage>-<kind>-<idx><ext>` (`packages/app/src/slices/revisions/downloads.ts:16-49`). Retained YouTube text records are served as stored, without the edit overlay (`packages/app/src/slices/revisions/downloads.ts:31-35`). Records are attachments with `nosniff`; `?inline=1` on an `application/pdf` answers `inline` for Open PDF (`packages/app/src/edge/http/revision-files.ts:48-55`). The revision `images.zip` takes selected images plus thumbnails whose index is within the revision's thumbnail count, in image order with thumbnails last (`packages/app/src/slices/revisions/downloads.ts:51-90`).
7. **Open folder.** Per output (`POST /api/projects/:id/open-folder`, `images.zip` opens the first existing image's folder) and per retained record (`POST /api/projects/:id/revisions/:revisionId/:recordId/open-folder`) reuse the download lookup, then `replyForFolder`; a cross-origin `Origin` gets 403 (`packages/app/src/edge/http/open-folder.ts:35-64`, `packages/app/src/edge/http/revision-files.ts:60-78`). Native: open the containing directory. Docker: walk each path segment with `lstat` (no symlinks, directories then a file), map to the host path, ask the host helper to open it (10 s timeout) and return the host path either way (`packages/app/src/edge/http/folder-location.ts:12-66`).
8. **Startup reconciliation.** `reconcileStorage` keeps every path named by `outputs`, `project_assets` (all revisions, not only the selection) and `stage_pieces.payload.file`. In the projects root it skips the `Backups` folder, dot-entries and `desktop.ini`/`thumbs.db`; when the projects root is outside the data dir, loose files stay too. Folders of unknown projects are removed; unnamed files in known projects are unlinked (`packages/app/src/slices/storage/reconcile.ts:14-76`). Staged files survive only while referenced and complete (state `staged`, same size); their draft attachments flip to `ready`, others to `reattach` with "Upload is missing or incomplete. Reattach the file." (`packages/app/src/slices/storage/reconcile.ts:78-106`). The same routine runs on demand via `POST /api/storage/cleanup` (Clean orphan files) (`packages/app/src/edge/http/storage.ts:208`, `packages/web/src/routes/settings.tsx:448-469`).
9. **Keep outputs only.** `outputRoles` are what a finished project is for: video, short_video, shorts, thumbnail, article_md/txt, sources, the four YouTube roles, document_pdf, audio_export, subtitles_srt/vtt (`packages/app/src/slices/storage/trim.ts:19-35`). Kept = outputs of every revision plus every user-supplied file (an asset named in any revision's content/config or the project config, or a legacy output with `original_filename`) (`packages/app/src/slices/storage/trim.ts:143-158`). Removable = files named by `project_assets`, `outputs` or piece payloads that are not kept; unnamed files are never touched here (`packages/app/src/slices/storage/trim.ts:161-184`). `GET /api/storage/projects/:id` returns outputs bytes, working bytes, removable count/bytes and `finished` (`packages/app/src/slices/storage/trim.ts:57-81`); `POST /api/storage/projects/:id/keep-outputs` unlinks the removable files and returns `files` and `bytesFreed` (`packages/app/src/slices/storage/trim.ts:83-98`). Settings → Backup & storage lists projects largest first with the same action; the project page shows Free space only when finished, not a bundled sample, and removable bytes > 0 (`packages/web/src/routes/settings-storage.tsx:16`, `packages/web/src/project/free-space.tsx:35-63`).
10. **Storage usage and trash totals.** `storageBytes`: `projects` = bytes under the projects root minus the Backups folder when it sits inside it; `data` = data dir bytes, plus projects when the projects root is outside the data dir; `staging` = staging bytes (`packages/app/src/slices/storage/portable.ts:1157-1172`). `storageUsage.byProject` covers live projects only (not in `project_trash`), newest first, each with directory bytes and its `projectStorage` split; `trash` = count of trashed projects and the sum of their folder bytes (`packages/app/src/slices/storage/portable.ts:1174-1205`, `packages/app/src/slices/admission/repo.ts:68`). Disk space shows "stored", project files as `projects − trash.bytes` (floored at 0), staged files, and when any are trashed "N deleted project(s) … in the trash, freed when removed for good" (`packages/web/src/routes/settings.tsx:563-590`).
11. **Trash (projects).** Delete on 07 Projects calls `DELETE /api/projects/:id` → `trashProject`, which inserts `project_trash(project_id, deleted_at)` inside `withProjectControl` (`packages/app/src/edge/http/projects.ts:138-152`, `packages/app/src/slices/trash/service.ts:73-87`). A trashed project leaves lists and the batch queue view; the runner holds it like a paused project (`packages/app/src/slices/batch/index.ts:20-30`, `packages/app/src/slices/trash/service.ts:69-72`). Restore deletes the row and ticks the runner so unfinished work and a queued item resume (`packages/app/src/edge/http/trash.ts:60-68`, `packages/app/src/slices/trash/service.ts:117-126`). Delete now runs `deleteProject` under the project control lock (`packages/app/src/edge/http/trash.ts:69-77`). The daily purge removes everything with `deleted_at` older than 30 days; `createTrashPurge.tick` purges when a day has passed since its last purge, `main.ts` calls it at start and hourly inside the updater's mutation gate (skipped while an update installs) (`packages/app/src/slices/trash/model.ts:10-11`, `packages/app/src/slices/trash/service.ts:288-323`, `packages/app/src/main.ts:710-729`). Shallow: prompts, entries, templates and schedules share the trash (restore renames to "Name (restored)", "(restored 2)"…; a schedule comes back paused with no next run and needs a live template) (`packages/app/src/slices/trash/service.ts:96-232`); their rules belong to their own scenarios.
12. **Removal for good.** `deleteProject` refuses `running` when `projectBusy` (an in-flight call or derived state `running`), removes the project folder and its render cache (`rmSync` recursive, `packages/app/src/slices/storage/delete-project.ts:54-58`), and only after success deletes the `projects` row; stages, attempts, pieces, outputs, revisions and assets cascade (`packages/app/src/slices/storage/delete-project.ts:35-71`).
13. **Export everything.** `GET /api/storage/export/summary` answers `ready:false` with the busy list instead of a failed download; `GET /api/storage/export` streams `slopify-backup-YYYY-MM-DD.tar` with exact `content-length` (`packages/app/src/edge/http/storage.ts:90-138`). `planBackup` refuses (`BackupBusyError`) while any project has a running stage, running revision work, a queued queue row or an in-flight call (`packages/app/src/slices/storage/backup-export.ts:88-111`). In one read transaction it snapshots: manifest (format, backup schema, app version, database version, backup id, per-project bytes); library part (exportable settings, prompts, entries, voices, document themes, narration aliases, templates and versions, schedules with runs and topics, library versions, channels, cast members/images, episode memories, channel videos, standalone usage, active Play drafts with complete staged uploads, image blobs, uploaded fonts); usage events except `install`; one part per project, holding that project's rows from `projectTables` — since 3.2.8 also `youtube_videos`, since 3.3.0 `upload_slots`, `video_stats` and `ab_results`; left out on purpose are `plan_limit_waits`, `plan_limit_waiters`, `prompt_softening`, `narration_retries`, `prepared_videos` and `project_set_aside` (`packages/app/src/slices/storage/backup-format.ts:38-83`); every project file; a SHA-256 list (`packages/app/src/slices/storage/backup-export.ts:109-199`, `packages/app/src/slices/storage/backup-export.ts:330-400`). Files are read 1 MiB at a time with `O_NOFOLLOW`; a file whose size changed since the plan ends the stream with an error (`packages/app/src/slices/storage/backup-export.ts:202-240`). Provider keys, the telemetry machine id, logs, the model cache, updates and staging leftovers are never read.
14. **Import.** `PUT /api/storage/import` dispatches on content type: `application/x-tar` → `importBackup`; `application/zip` → legacy `importPortable` capped at 100 MB; anything else 415 (`packages/app/src/edge/http/storage.ts:139-207`, `packages/app/src/slices/storage/portable.ts:62`). `importBackup` refuses a concurrent import (409), clears and recreates `<dataDir>/imports/<id>`, validates every JSON part with zod, refuses a newer backup or database version, refuses when free space < needed + 64 MiB, then commits rows and renames staged files into place in one synchronous step (`packages/app/src/slices/storage/backup-import.ts:159-175`, `packages/app/src/slices/storage/backup-import.ts:276-282`, `packages/app/src/slices/storage/backup-import.ts:667-695`). Merge rules: a project whose id exists is skipped and reported; a library item with a taken name comes in as "<name> (imported)", identical ones are skipped; settings only fill unset keys; schedules come in paused; usage is added once per backup id (`backup_imports`) and marked delivered; the default channel row is replaced (`packages/app/src/slices/storage/backup-import.ts:66-83`, `packages/app/src/slices/storage/backup-import.ts:457-458`, `packages/app/src/slices/storage/backup-import.ts:830-854`, `packages/app/src/slices/storage/backup-import.ts:914-928`). `exportPortable` still exists but no route calls it, so nothing writes a .zip any more (`packages/app/src/slices/storage/portable.ts:195`).
15. **Scheduled backups.** Config key `backups.config`, status key `backups.status`; default off, 03:00, server zone, keep 5 (1–30), folder `null` = `paths.backups` (`packages/app/src/slices/backups/model.ts:8-48`). `main.ts` ticks every 60 s (`packages/app/src/main.ts:703-708`). `decideBackup`: off → none; one due per daily slot when no success since the slot; a slot before `enabledAt` does not count; a slot missed while stopped is caught up unless a success is < 20 h old; nothing within 2 min of boot; a failed slot retries after 1 h, a `waiting` one after 10 min (`packages/app/src/slices/backups/schedule.ts:6-75`). A run reuses `planBackup`/`streamBackup`; busy projects record `waiting` with their names (`packages/app/src/slices/backups/service.ts:138-152`, `packages/app/src/slices/backups/service.ts:243-281`). Writing: create folder `0700`, remove `.slopify-backup-…tar.partial` leftovers, check free space ≥ archive size, write `.<name>.partial` with `O_EXCL|O_NOFOLLOW` mode `0600`, yield per chunk, fsync, rename to `slopify-backup-YYYY-MM-DDTHHMMSSZ.tar`, fsync the folder, then prune oldest matching files down to `keep` (`packages/app/src/slices/backups/files.ts:9-139`, `packages/app/src/slices/backups/service.ts:89-136`). Back up now (`POST /api/backups/run`) answers 202 and the screen polls (`packages/app/src/edge/http/backups.ts:31-40`).
16. **Moving files (native).** `POST /api/storage/files/move` with `target` `"documents"` or an absolute path starts a background move and returns 202 with the view (`packages/app/src/edge/http/storage-files.ts:21-35`). `targetProblem` refuses relative paths, control characters, system/shared folders, anything inside the data dir, the current root, overlapping folders, a non-empty `Projects`/`Backups` target (unless resuming the stored `files.move`), a file in the path, or no write permission (`packages/app/src/slices/storage/files-location.ts:565-611`). Busy projects (409), a running update (409), or free space < pending bytes + 64 MiB (400) also refuse (`packages/app/src/slices/storage/files-location.ts:203-250`). `runMove` copies each file via `*.slopify-partial` + rename preserving mtime, never copying `.render-cache` (`packages/app/src/slices/storage/files-location.ts:418`), skipping files already present with equal size and mtime; verifies every file by size and SHA-256 (one re-copy); refuses to switch if a project became busy or any source file changed; then writes `files.location`, clears `files.move` and repoints `Paths`. The old folder is never changed and is reported as `oldFolder` (`packages/app/src/slices/storage/files-location.ts:444-519`). Docker refuses with the installer command `npx @gentbajko/slopify@latest update --docker --projects-dir documents` (`packages/app/src/slices/storage/files-location.ts:180-181`, `packages/app/src/slices/storage/files-location.ts:331-337`).
17. **Diagnostics.** `GET /api/diagnostics` downloads `slopify-diagnostics.json`: app/schema versions, platform, Node major, provider id/family/name/readiness and configured CLI path, project total, catalogue status (`packages/app/src/edge/http/diagnostics.ts:10-40`).

## Branches

- Missing externally deleted bytes: history and metadata stay; a direct download returns 404 with "use More → make it again" (current) or "Choose what to remake" (retained); a zip skips missing entries and returns 404 `no-images` when none remain (`packages/app/src/edge/http/files.ts:79-93`, `packages/app/src/edge/http/revision-files.ts:81-91`). No download or restore silently starts a rebuild.
- A multi-file export is reusable only if all retained bundle members are available and ready (`packages/app/src/slices/rebuild/recipe-work.ts`).
- Disk/DB failure before publication preserves the previous committed revision; only newly allocated unreferenced assets are discarded (`packages/app/src/slices/storage/assets.ts:88`, `packages/app/src/slices/revisions/mutation-prepare.ts`).
- Files location `data-dir` vs `root`: in `data-dir` Backups sits inside `projects/` and a move copies it as its own pair; loose files in a user-visible projects root survive reconciliation (`packages/app/src/slices/storage/files-location.ts:383-399`, `packages/app/src/slices/storage/reconcile.ts:51-58`).
- Keep outputs only on a project that is not `done`/`partial`, has an in-flight call, or has revision work `running` or `pending` with `dispatch_state='allowed'`: 409 (`packages/app/src/slices/storage/trim.ts:100-112`, `packages/app/src/edge/http/storage.ts:81-86`).
- Backup folder: a folder inside the projects root other than its Backups folder, or inside staging, logs or `models`, is refused on save (400, field `folder`) and skipped by the tick (`packages/app/src/slices/backups/folder.ts:26-40`, `packages/app/src/slices/backups/service.ts:195-208`, `packages/app/src/slices/backups/service.ts:254`). In Docker, `hostFolder` maps the folder to the host only when it is inside a shared mount, else `null` (`packages/app/src/slices/backups/folder.ts:45-61`).
- Native file-manager launch failure: 503 with desktop-session guidance. Docker without a verified host projects folder: 503; missing/symlinked output path: 404 (`packages/app/src/edge/http/folder-location.ts:19-82`).

## Unhappy paths

- Trashing a running project: 409 "Use Cancel run on the project page first" (`packages/app/src/edge/http/projects.ts:141-151`). Delete now: 404 not in trash, 409 running, 500 `files` with the OS message when the folder will not go; the project stays in the trash (`packages/app/src/edge/http/trash.ts:19-47`). Partial `rmSync` may already have removed some bytes; the row stays so Delete now can be pressed again. The purge logs a failed item (`trash.purge`) and retries it next pass (`packages/app/src/slices/trash/service.ts:292-303`).
- Export while busy: 409 naming up to three projects "and N more"; unexpected failure 500 with free-space/diagnostics guidance (`packages/app/src/slices/storage/backup-export.ts:60-67`, `packages/app/src/edge/http/storage.ts:106-115`).
- Import: damaged, out-of-order, newer, too-large-for-free-space or concurrent backups are refused (`BackupImportRefused`, 400/409/422); any other failure is 500 "nothing in this install changed"; the upload reader is cancelled so the rest of a large file is not read (`packages/app/src/edge/http/storage.ts:177-206`). Legacy zip empty or > 100 MB: 413; unreadable: 400 (`packages/app/src/edge/http/storage.ts:149-175`).
- Scheduled backup failures are recorded with `explain()`: not enough space (with needed/free), `ENOSPC`/`EDQUOT`, `EACCES`/`EPERM`/`EROFS`, `ENOTDIR`/`EEXIST`, a file changed mid-copy, stop during write (partial removed), or unexpected (`packages/app/src/slices/backups/service.ts:329-361`). A prune failure keeps the backup as succeeded with a detail line (`packages/app/src/slices/backups/service.ts:112-117`). Back up now refuses 409 while shutting down, while a backup is being written, while projects are busy, or while an update installs; 400 on a bad folder (`packages/app/src/slices/backups/service.ts:209-242`).
- File move: a copy mismatch after one re-copy, a project starting, or a source change during the copy fails the move with "Continue moving" guidance; the stored `files.move` target lets the next attempt resume, and the view reports `interrupted` after a restart (`packages/app/src/slices/storage/files-location.ts:481-512`, `packages/app/src/slices/storage/files-location.ts:285-328`). A second move while one runs: 409 (`packages/app/src/slices/storage/files-location.ts:338-343`). A damaged `files.location` value stops startup with a message naming the settings row (`packages/app/src/slices/storage/files-location.ts:55-65`).
- Keep outputs only: an `unlinkSync` error is not caught; files removed before it stay removed (`packages/app/src/slices/storage/trim.ts:90-96`).
- `POST /api/storage/cleanup` runs `reconcileStorage` with no busy-project check (`packages/app/src/edge/http/storage.ts:208`).
- A file whose path resolves outside its root throws an internal-error message pointing to Download diagnostics (`packages/app/src/slices/storage/layout.ts:38-47`).

## State transitions

- Staged file → registered immutable project asset when an admission or revision commits; output records stay retained while the selected manifest changes (`packages/app/src/slices/revisions/mutations.ts:58`).
- Project: live → trashed (`project_trash` row) → live (Restore) or removed (Delete now / purge: folder, then row and cascades). Removal is refused while busy; trashing is refused while busy (`packages/app/src/slices/trash/service.ts:73-87`, `packages/app/src/slices/storage/delete-project.ts:44-71`).
- Finished project: working files present → removed by Keep outputs only; a later remake makes them again first (`packages/web/src/routes/settings-storage.tsx:109-111`).
- Files location: `data-dir` or `root A` → (`files.move` pending: copying → verifying → done | failed | interrupted) → `root B`; `files.location` changes only at the end of a verified copy (`packages/app/src/slices/storage/files-location.ts:116`, `packages/app/src/slices/storage/files-location.ts:515`).
- Backup status `lastResult`: null → `waiting` | `succeeded` | `failed`, per slot (`packages/app/src/slices/backups/model.ts:53-66`).
- Full-backup import adds projects not already here with their rows and files verbatim and never changes an existing project (`packages/app/src/slices/storage/backup-import.ts:66-83`).

## Invariants

- Every project asset resolves under its project directory; record/asset ownership is checked in addition to path containment (`packages/app/src/slices/storage/layout.ts:38-47`, `packages/app/src/slices/revisions/downloads.ts:22-41`).
- Save, Restore and downloads never submit providers.
- Historical and currently selected references both protect assets during reconciliation; the Backups folder is never reconciled (`packages/app/src/slices/storage/reconcile.ts:17-56`).
- Keep outputs only never removes a user-supplied file or a file no record names (`packages/app/src/slices/storage/trim.ts:11-15`).
- A project folder is removed before its rows, never after; rows removed first would orphan files (`packages/app/src/slices/storage/delete-project.ts:52-69`).
- Scheduled-backup pruning and leftover sweeps touch only names matching the feature's exact patterns, never an Export everything download or a renamed file (`packages/app/src/slices/backups/files.ts:6-10`).
- A move never changes the old folder; `files.location` switches only after every file's SHA-256 matches (`packages/app/src/slices/storage/files-location.ts:438-519`).
- An import only adds: existing projects, library items and settings are never replaced (`packages/app/src/slices/storage/backup-import.ts:66-80`).

## Managed Docker project storage

The installer binds the host projects folder at `/data/projects` (and, for a brand-new install that takes the Documents default, a sibling `Backups` at `/data/backups`); SQLite, credentials, logs, staging and models stay in the named volume (`packages/app/src/edge/docker-install/activation.ts:27-66`, `packages/app/src/edge/docker-install/apply.ts:156-163`). The projects folder is, in order: `--projects-dir` / `SLOPIFY_DOCKER_PROJECTS_DIR`, the recorded install's folder, then `<Documents>/Slopify/Projects` (`<Documents>/Slopify/<name>/Projects` for another container name), falling back to `~/Slopify/Projects` when no Documents folder is known; `--projects-dir documents` means the Documents default (`packages/app/src/edge/docker-install/run.ts:44-61`, `packages/app/src/edge/docker-install/run.ts:189-193`, `packages/app/src/edge/docker-install/apply.ts:144-153`). A new folder must be empty and must not contain or sit inside the current one (`packages/app/src/edge/docker-install/apply.ts:163-179`).

The install snapshots the data volume to a recovery volume, then `publishProjects` copies the old host folder (or the files a plain `docker run` kept inside the volume) into `.slopify-projects-<id>` beside the target, sets ownership to the invoking UID/GID, compares a tree digest with the source, and renames it into place; the source is never changed (`packages/app/src/edge/docker-install/apply.ts:263-265`, `packages/app/src/edge/docker-install/apply.ts:497-541`). Any failure rolls back to the previous container and data and reports the recovery volume (`packages/app/src/edge/docker-install/apply.ts:342-356`). While a candidate's activation is pending, boot defers reconciliation (`packages/app/src/main.ts:279-282`). The container validates that `/data/projects` is a real mount and the host path is absolute and comma-free before reporting host locations (`packages/app/src/edge/docker-install/activation.ts:38-66`).

This is Slopify-managed storage, not a synchronization folder: reconciliation removes unregistered project folders and files. The host-location response exposes only the owned record's directory.

## Font and model lifetime

System fonts are read from standard OS directories (`packages/app/src/slices/fonts/discovery.ts:22`); uploaded `.ttf`/`.otf` files are limited to 32 MiB, validated and stored as `uploaded-<sha256>` (`packages/app/src/slices/fonts/upload.ts:35-42`, `packages/app/src/slices/fonts/model.ts:15`). Each caption export keeps a `subtitle_font` snapshot (`fonts/selected<ext>`), so history remains usable after a system font disappears (`packages/app/src/slices/subtitles/prepare.ts:103`, `packages/app/src/slices/subtitles/prepare.ts:149`). Uploaded fonts (in `<dataDir>/fonts`) and the alignment-model cache (`<dataDir>/models/`) are outside project folders, so project removal leaves them (`packages/app/src/kernel/paths.ts:78-84`).

## Outcomes & side effects

Storage mutations write local files and SQLite ownership records. Downloads, usage and diagnostics are read-only; Open folder asks the host OS (or the Docker host helper) to reveal an owned directory. Keep outputs only and Delete now free disk space; trashing frees none until removal. Scheduled backups write archives into the backups folder and delete their own oldest archives. A move leaves a full old copy for the user to delete. Import only adds.

## Dimensions not in play

- Credentials: a backup carries no provider keys; they must be entered again after an import (`packages/app/src/slices/storage/backup-import.ts:79`).
- Quotas: storage usage imposes no quota; retained revision history has no automatic expiry; only the trash (30 days) and scheduled-backup `keep` expire anything.
- Money and notifications: no storage action moves money or sends an outbound notification.
- Remote storage: no cloud or network storage target exists; every path is local to the host.
